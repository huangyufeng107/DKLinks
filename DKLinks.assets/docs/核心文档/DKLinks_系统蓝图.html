1. 平台定位与交付范围

D客连面向汽车品牌的投放与线索运营。平台维护品牌、门店和合作方关系，帮助运营配置排期与供应商目标，执行适用的接收、培育和门店下发规则，并通过锁单核查、日志和报表对照计划与结果。经确认的经营结论可以用于后续排期和策略调整。

阶段覆盖与交付边界
原型现状覆盖下文 8 个业务域，数据和执行结果来自浏览器本地配置或样例。
目标设计各业务域需确认主数据与操作权限、配置发布、跨域数据关联和历史追溯。服务端持久化、并发控制及外部接口依赖通过联调逐项核实。
后续评估逐笔计费、门店额度与资源包、动态定价、对账及真实收付款、人工坐席拨打与派单、持续回池、企微短信、到店成交闭环。根据运营确认确定后续范围。下游到店、试驾或成交回传列入后续业务闭环。

2. 系统上下文

系统范围为 D客连平台。运营和管理员在平台内维护资料、配置投放、核查执行与分析结果。渠道、数据组、AI 外呼系统及品牌通道通过各自契约提供源事实或执行外部动作。

下游接收方由品牌通道配置决定，可经线索中心或直接对接品牌接口。数据组提供评分或锁单的源事实，D客连负责关联、快照与业务统计。品牌和门店是平台维护的业务对象。厂商或线索中心提供下发受理回执。门店端接收后的到店、试驾及成交归属仍按外部契约确认。运营可按授权核对排期、线索、日志、锁单和报表。

5. 平台治理

治理主题适用范围与规则目标控制与验收
身份与数据范围区分平台操作账号、渠道接入身份和报表业务账号。账号与角色控制动作权限，品牌、排期、供应商或门店范围约束实际可见数据。由服务端校验写操作与查询范围，按权限返回数据和导出结果。各类角色可见范围待权限矩阵确认。
主数据与字典品牌、车系、区域和门店关系供多域复用。状态码、外呼通道字典和业务字段映射各自维护并保留来源。验证主数据更新后的引用关系、停用状态及历史查询语义。实际主数据同步与责任方需实施确认。
配置生效与历史项目策略草稿供核对，已发布策略供后续线索使用。其他品牌字段映射、门店或报表配置按各自规则生效。保存业务发生时依据。查询历史处理使用保存的信息，配置变更以可追溯记录说明何时及影响哪些业务。
操作留痕与敏感数据把导入、发布、人工决定、补发、锁单改判和导出关联至操作者、对象、时间与结果。完整手机号、话单明细和原始报文受控访问。日志及查询显示遵循对应授权和脱敏规则。
报表口径与回查经营汇总按相同范围与来源读取。线索量按线索标识去重，有效锁单按锁单唯一标识去重。供应商累计达标和报表时段统计分别说明范围，保留原传、派生归属及对应明细。

6. 数据与归属

此处定义逻辑对象、关联键与事实归属，供接口和物理数据模型设计使用。

对象权威记录及关联键生命周期与读取边界
主数据与合作方D客连管理品牌、车系、城市、区域、门店、开发者和报表账号等配置。外部标识映射及同步责任由对应方确认。各域通过稳定的业务标识引用；保存历史事件时保留所用归属。
投放排期与供应商目标D客连维护排期、项目目标、供应商分配、SmartCode 关联及处理策略。排期归属供线索准入使用，原传有效锁单累计量用于同一排期内的供应商达标判断。
经营指标与权限报表基于线索、下发及锁单记录按当前范围汇总。角色、权限与业务账号分别维护。指标可回查明细；角色和数据范围共同约束读写。报表维度或账户变更须核对历史范围。
接收记录渠道提供来源线索 ID。D客连保存渠道标识、接收记录 ID、接收判定和时间；来源渠道＋来源线索 ID 识别重复提交，具体作用域在契约中确认。Excel 同样使用原供应商身份及原来源 ID，保存批次和操作人。拒绝入库只查接收记录及命中依据。
正式线索与派生D客连以平台线索 ID 标识记录，派生线索另有独立 ID，并关联原线索和目标门店。原传及派生的发送结果分别记录；派生引用原线索检测和外呼依据，供应商传输量及成本只归原传。
配置与判定快照D客连保存本次排期、配置来源／版本、规则命中、外呼等待、评分、下发映射与决定。发布或调整影响后续处理；历史解释读取当时证据，缺失项显示「未记录」。
外呼任务与话单AI 外呼系统提供任务与话单源事实；D客连保存平台关联、外部任务 ID、每次通话、状态及结果快照。一项任务可关联多条线索。等待期限和最终处理决定按线索保存。通话状态、标签、小结及任务状态分别记录。
下发记录与尝试D客连保存下发业务 ID、线索及目标门店、规则依据、尝试序号、请求标识和结果。厂商回执是确认已下发的依据。原传、派生及重试均可追查。补发沿用既有下发业务标识，并追加尝试记录。
有效锁单数据组提供锁单源事实及唯一标识；D客连按锁单唯一标识去重，记录归属、来源、关联线索和入库时间。排期＋供应商累计统计只纳入原传有效锁单；派生有效锁单单列。已入库明细供查询追溯。

8. 专项运行场景 · 线索接入与下发

本章详述线索接收、培育和下发专项。平台其他业务如何交接，见 跨域协作。

从接收判定到下发结果

  1. 接收与归属。完成接收校验并保存依据后返回接收判定。准入核对包含来源 ID、黑名单及排期归属。号码检测、AI 外呼与实际下发位于后续处理链路。拒绝入库保留接收及命中记录。
  2. 供应商达标。CPQL／CPO 按量付费排期按「排期＋供应商」的原传有效锁单累计量判断。达标后的新线索仅接收并记录原因，去重、检测、外呼及下发未执行，也不生成派生线索。已有下发任务按原安排执行。数据缺失时查询显示「待接入锁单数据」，生产判断的缺失处理待接口定稿。
  3. 执行有效策略。品牌能力关闭或无可用去重规则时跳过对应环节。品牌能力恢复后，运营显式开启并发布项目策略。仍开启的有效环节如必要配置不完整，保留异常依据并按发布策略处理。
  4. 确定门店并下发。原线索满足下发条件后，独立校验原传门店；一发多再从适用范围选派生门店，排除原传及重复目标。逐店校验范围、可用性与同客同店重复下发。比例名额保留计划与实际使用记录，未尝试名额由下一条续接。

允许下发的运行时序

外呼回调、超时或人工处理竞争本条最终决定时，以首次有效提交为准。后到结果留作证据。达到供应商锁单目标的新线索结束于「仅接收」，不进入图中的外呼和下发。查看达标分支 · 查看独立等待及结果分支

号码检测与预评分

号码检测和厂商字段映射各自配置。检测关闭时跳过，品牌明确状态按其动作继续或停止，服务异常保留 UNKNOWN。有效映射决定是否传递结果，厂商必填字段在下发时校验。需要评分时使用本次取分，最多等待 6 分钟，然后按原流程或配置的无分线路继续；迟到评分保留事件。

任务复用、独立等待与人工决定

通过前置判断且启用外呼后，按同品牌及完整手机号判断在途任务。符合条件时关联原任务，并沿用该任务创建时的结果规则和下发映射快照。冷却期命中时复用最近可用结果，按新线索接收时的规则快照重新判断。每条线索独立保存等待起点、期限和兜底，首条从任务创建成功计时，关联线索从自身准入并关联时计时。结果无法核验时转人工核查。人工决定记录结论及备注，允许继续下发或仅接收。晚到事件保留记录且不覆盖已生效决定。

状态维度展示依据
线索结论待处理、处理中、待人工处理、仅接收、下发失败或已下发等，读取本条处理结论及原因。厂商回执满足品牌受理条件后才确认已下发。
环节进度已通过有执行依据；已跳过有规则依据；已停止有终止原因；未执行为前序停止或尚未到达；处理中有等待或排队事实；未记录为历史依据缺失。
运营追溯规则命中、外呼任务及话单、下发尝试和锁单记录各自提供证据。仅凭线索末态无法确定发生的具体环节。

9. 一致性与防环路

控制点一致性原则应留证据
接收与重复来源原子创建或复用接收记录；同一提交重试保持原接收结果和独立的后续状态。接收去重规则另行判断。来源键、原接收记录 ID、重复识别结果。
任务与最终动作同品牌＋完整手机号的有效在途任务需并发控制。重复回调按事件键判重，超时、回调和人工操作只允许提交一次有效线索决定。外部任务 ID、原始事件键、到达时间、有效决定和迟到记录。
派生与下发原传与派生逐门店落账，补发复用原下发业务标识。遇回执不明时先查证再重发。已发出的请求保留执行历史，后续操作追加事件。目标门店、下发业务 ID、重试序号、回执或失败原因。
跨系统回流向线索中心提供双方约定的来源与平台线索 ID。接收方识别同源事件，避免回流重新创建线索与触发下发，具体字段和事件契约由双方确认。关联 ID、来源识别结果及重复转发联调样例。

接入响应代表性峰谷流量下并行提交正常、重复及被拒请求。统计入口收到请求到接收响应的 P95，同时核对重复提交的结果。接入压测报告，吞吐与 P95 门槛由研发和运维按实测确认。
处理积压模拟外部依赖变慢，观测最老待处理任务年龄、积压峰值和恢复时间。运行指标与告警记录，告警门槛和恢复目标由运维确认。
并发及回执同一来源重复提交，回调、超时与人工决定并发，模拟厂商迟到回执。只产生一条有效接收事实、一次有效线索决定和对应门店的合法下发。比对记录标识与尝试历史。
灾难恢复对隔离环境执行备份恢复和处理任务重启，核对接收、锁单和下发证据。记录实测恢复时长、可恢复时间点、账实差异和重复数。生产 RTO 与 RPO 待评审。
授权与审计以无授权身份查询跨品牌线索、导出和提交人工决定，再以授权角色执行。越权被拒，授权行为按范围生效并可回查操作者、对象及时间。

故障处置与恢复

异常处置动作保留证据
号码检测超时或不可用保存 UNKNOWN 和失败原因，沿当前业务策略继续；检查是否为单条异常或依赖故障。检测请求标识、错误分类、检测结论与后续事件。
评分超过等待上限按无分路径继续，迟到分数只留痕。等待起止、无分原因、适用兜底和迟到记录。
厂商回执未知优先按品牌契约查证，必要时人工核对。符合重试条件后复用同一业务标识。尝试、请求标识、查询证据、最终回执。
锁单同步延迟或缺失显示数据缺失或不及时的依据，不将空值当成零。生产停发判断口径由数据组与排期运营确认。最近同步时间、缺失范围、原传锁单统计明细。
异步任务重启从已保存状态恢复，检查是否已有最终决定或发送结果，再按幂等约束继续。恢复前后关联 ID、事件顺序、发送尝试和差异记录。

厂商回执由品牌对接核查，锁单延迟由数据组核对批次及归属。恢复后由运维核对积压、重复下发和重复入库。

平台域验收

业务范围核对对象与操作通过依据证据与阶段
基础资料与合作方选择一组品牌、车系、区域、门店、开发者及报表账号，核对在投放和接入配置中的选项及关联。关联使用同一业务标识和适用范围，能区分接入身份与业务账号。原型核对候选与回显；正式验收补主数据同步及历史关联证据。
